# Hospital Information System (HIS)

The Medic1905-update follow-up is documented in [HIS_UPDATE.md](./HIS_UPDATE.md). It extends the existing application with patient-linked attachment/image fields, diagnostic verification and release revocation, protected-record filtering, template concurrency/mandatory-rule safeguards and fail-closed scanner handling. Existing hospital template versions and signed documents are not rewritten.

Extends the facility portal (`/lab`) into a configurable multi-hospital HIS. Everything reuses the existing Clerk auth, facility membership/permission model (`src/lib/facility-auth.ts`, `src/lib/facility-staff.ts`), audit log, notifications and private S3 storage.

## What is implemented

| Area | Where | Notes |
|---|---|---|
| Hospital settings (branding, letterhead, numbering prefix, language, date format, page size, terminology, optional modules, triage protocol, overdue threshold, retention category) | `/lab/hospital-settings`, `GET/PUT /api/facility/his/settings` | Per facility; every change snapshotted in `hospital_settings_revisions`. |
| System template catalogue, groups A–P (~300 document types) | `src/lib/his/catalogue.ts` | Read-only defaults. Consent (F), lab (G), imaging (H), physiological (I), endoscopy (J), discharge (O), operative (E) have specific structures; others use generic/SOAP scaffolds. Specialty packs (N) carry a "clinical review required" notice. |
| Hospital template library + builder | `/lab/clinical-documents`, `/lab/clinical-documents/templates/[id]`, `/api/facility/his/templates/**` | Adopt (clone) from catalogue, custom, clone, import/export JSON. Section/field builder (text, textarea, number+unit, date, datetime, select, multiselect, checkbox, table, workflow signatures, patient-linked image/attachment references), required flags, conditional sections, translations, signature rules, review requirement, sensitivity, page size, preview. Lifecycle DRAFT → IN_REVIEW → APPROVED → PUBLISHED → RETIRED; guarded transactions serialize saves and lifecycle changes. Locked fields/signatures from source and hospital definitions cannot be removed, hidden or weakened. Optional independent approval. |
| Clinical documents | `/lab/clinical-documents/[id]`, `/api/facility/his/documents/**` | Facility-numbered (`PREFIX-YYYY-NNNNNN`), linked to patient and optionally encounter/admission. Autosaved drafts (author only), submit (required-field validation), clinical review (independent reviewer if configured), signatures, finalize (all required signatures bound to the SHA-256 of the content), amendment (new linked revision; original becomes AMENDED only when the amendment is finalized), release to patient, entered-in-error. Every step in `clinical_document_events` and the audit log. Optimistic concurrency on every transition. |
| Signatures | `document_signatures` | Staff sign as themselves (authenticated electronic). Patient/representative/witness/interpreter wet-ink signatures are recorded as *handwritten, attested by* the staff member who witnessed them. Department-head signature requires `APPROVE_DOCUMENTS`; nobody is shown as head/approver unless they signed. Returning to draft revokes signatures. |
| Print and PDF | `/lab/clinical-documents/[id]/print`, `GET /api/facility/his/documents/[id]/pdf` | pdf-lib + embedded DejaVu Sans (Unicode), letterhead, patient/encounter header, tables, page numbers, document id, signature block with only real signatures, "NOT SIGNED" for unmet ones, watermark on draft/preliminary/superseded/void. |
| Records package | `POST /api/facility/his/patients/[id]/package` | Selected FINAL documents in one PDF with index + SHA-256 manifest; needs `RELEASE_DOCUMENTS` and a patient authorization reference. |
| Patient portfolio | `/lab/patients/[id]` | Demographics, encounters/admissions, documents by group, media, insurance (insurance staff), timeline, access history (`VIEW_AUDIT`). Shows only this facility's records. |
| Identity verification | `POST /api/facility/his/patients/identify` | Exact case number **and** date of birth. No fuzzy name matching; no automatic merges. |
| Diagnostic media | `/lab/media`, `/api/facility/his/media/**` | Format registry (`src/lib/his/media-formats.ts`): PDF, DOC/DOCX, XLS/XLSX, CSV/TXT, JPEG, PNG, TIFF, DICOM, MP4/MOV, WAV/MP3, SCP-ECG, HL7 v2, FHIR JSON/XML; extension + MIME + magic bytes must agree; ZIP/executables refused; per-format size limits; facility storage quota. Browser SHA-256 → presigned PUT to a patient-scoped staging key → server re-checks signature, copies to a server-only key, re-hashes and compares, optional fail-closed malware scan → metadata row. Files at or above the multipart threshold (default 64 MB) instead open a resumable multipart session: parts upload through presigned part URLs, completion is verified against the storage service's own part list (never client ETags), retries resume only the missing parts, and a cleanup job aborts expired sessions. Duplicate detection by checksum. 24 diagnostic categories; therapy records flagged separately. 60-second signed URLs; inline preview only for safe formats. Reviewers verify results; release requires VERIFIED/AMENDED status. Release can be revoked and is automatically cleared on downgrade. |
| Encounters & queues | `/lab/encounters`, `/api/facility/his/encounters/**` (hospitals) | Care priority (emergency…elective) separate from encounter type and from triage. 17 workflow statuses with guarded transitions and history. Triage categories only from the hospital's configured approved protocol. Dashboards: emergency, urgent, planned, elective, inpatient, outpatient, waiting, all; filters by department, clinician, triage category, payer, status, dates; priority sorting, time since registration/update, overdue flag; auto-refresh. |
| Payer classification | `/lab/insurance`, `/api/facility/his/coverage/**` | 10 payer categories, primary/secondary, provider, masked member number, coverage dates, eligibility + verification history, referral/preauth, authorization number/expiry, claim status, billing responsibility, co-pay/out-of-pocket. Classifications are ended, never overwritten; encounters snapshot the payer that applied. |
| Nursing | `/lab/nursing`, `/api/facility/his/nursing/**` | Structured observations from a fixed type/unit registry (`src/lib/his/observation-types.ts`): each entry stores the clinical timestamp, value, registry-fixed unit, author and optional note. Validation is format-only — no clinical thresholds, scores or automatic flags. Care tasks with a guarded lifecycle (DUE → IN_PROGRESS → COMPLETED, with DEFERRED/ESCALATED side exits and reopen), assignment and due times. Shift handovers record the summary and attach the patient's open tasks. Writing requires `RECORD_NURSING`; the chart is identified by exact case number + date of birth. |
| Pharmacy | `/lab/pharmacy`, `/api/facility/his/medication-orders/**` | Medication orders (name, strength, dose, route, frequency, duration, prescriber, notes) with a guarded workflow DRAFT → SUBMITTED → REVIEWED → DISPENSED → COMPLETED (cancellable at live stages). Submitting requires `ORDER_MEDICATIONS`; reviewing and dispensing require `REVIEW_MEDICATIONS`; only the prescriber can cancel. Each worklist entry carries the patient's recorded allergies for visibility. On creation the response carries advisory safety alerts: exact-name matches against this facility's own configured active interaction rules (either direction), substring allergy alerts against the patient's recorded allergens, and the facility formulary match (incl. high-alert flag) — rules are hospital-configured only, never invented, never dosing advice, and never block. |
| MAR administration recording | `/lab/nursing` (MAR tab), `POST/GET /api/facility/his/medication-orders/[id]/administrations` | Nurses with `ADMINISTER_MEDICATIONS` record administration entries (GIVEN with dose, REFUSED, HELD with reason, or NOT_GIVEN with reason) against a live order. Entries are attributed (author + clinical timestamp, validated not in the future), append-only (no edits/deletes), and listed as a per-order MAR log. Workflow recording only — not a closed-loop control system. |
| Formulary & interaction rules | `/lab/pharmacy`, `GET/POST /api/facility/his/formulary`, `PATCH /api/facility/his/formulary/[id]`, `GET/POST /api/facility/his/interaction-rules`, `PATCH /api/facility/his/interaction-rules/[id]` | Pharmacists with `MANAGE_FORMULARY` maintain the facility formulary (name, strength/form, high-alert flag; entries retired/restored, never deleted) and advisory interaction rules (pairs of medication names, severity, description; self-pairs and duplicates rejected). Rules are the hospital's own configuration — the system ships none and invents none. |
| E-prescribing outbox | `GET/POST /api/facility/his/eprescribing` | Submitting an order enqueues an append-only outbound snapshot (order + patient case number + prescriber) in `e_prescription_outbox`. Delivery requires an `EPRESCRIBING_ENDPOINT`; without it entries stay `PENDING` and the queue honestly reports `endpointConfigured: false`. Failed attempts are recorded without ever claiming live transmission. |
| Analytics | `/lab/his-analytics` (`VIEW_ANALYTICS`) | Aggregates only: volumes by department/type/priority, admissions/discharges, document status/group, unsigned documents, creation→finalization time, payer mix, media categories, template usage. |
| Patient portal | `/patient/documents`, `/api/patient/clinical-documents/**`, `/api/patient/media/[id]` | Only FINAL/AMENDED documents explicitly released, and released media; PDF download; audited. |
| Notifications | `CLINICAL_DOCUMENT` type | Documents awaiting review/signature (staff) and released documents (patient). Messages contain no clinical detail. |

## Roles and permissions

New facility roles: `RADIOLOGIST`, `DIAGNOSTIC_SPECIALIST`, `PHARMACIST`, `SURGEON`, `DEPARTMENT_HEAD`, `MEDICAL_RECORDS_OFFICER`, `BILLING_OFFICER`, `INSURANCE_OFFICER`. New permissions: `AUTHOR_DOCUMENTS`, `REVIEW_DOCUMENTS`, `SIGN_DOCUMENTS`, `APPROVE_DOCUMENTS`, `RELEASE_DOCUMENTS`, `MANAGE_HOSPITAL_SETTINGS`, `MANAGE_ENCOUNTERS`, `MANAGE_INSURANCE`, `UPLOAD_MEDIA`, `VIEW_ANALYTICS`, `RECORD_NURSING`, `ORDER_MEDICATIONS`, `REVIEW_MEDICATIONS`, `ADMINISTER_MEDICATIONS` (nurses, MAR), `MANAGE_FORMULARY` (pharmacists) (mapping in `src/lib/facility-staff.ts`). All enforcement is server-side (`requireHisAccess`); pages only shape navigation. Template groups are limited by organization type (labs: G/F; diagnostic centres: F/H/I/J; hospitals: all). Specially protected documents are visible only to their author and reviewers.

**Tenant isolation:** every query filters by the caller's facility; patient-level actions require an existing care relationship (`assertPatientLinked`); foreign ids return 404. Storage keys are facility+patient scoped and never exposed.

## Database

Migration `prisma/migrations/20261026120000_his_foundations` (additive: new enums/tables, new enum values on `FacilityStaffRole` and `NotificationType`). Nursing/pharmacy migration `20261101000000_his_nursing_pharmacy` and MAR/formulary/e-prescribing migration `20261101010000_his_mar_formulary_eprescribing` (additive: `MedicationAdministration`, `FormularyItem`, `MedicationInteractionRule`, `EPrescriptionOutbox` tables and back-relations). Apply with `npm run db:deploy`. Rollback: the migrations only add objects; to roll back the app, redeploy the previous commit (new tables are ignored). To remove the schema, drop the new tables/types manually after exporting data — enum values added to existing types cannot be dropped in Postgres without recreating the type.

## Configuration

- `MALWARE_SCAN_URL` / `MALWARE_SCAN_TOKEN` (optional): scanner webhook; otherwise uploads are recorded `NOT_SCANNED`.
- Existing S3 variables are required for media uploads. Add a lifecycle rule deleting objects under `medical-media/staging/` older than 1 day.
- `HIS_MULTIPART_THRESHOLD_BYTES` (optional): files at or above this size upload through resumable multipart parts (default 64 MB). The bucket CORS policy must allow PUT for part uploads.
- `HIS_MEDIA_QUOTA_BYTES` (optional): facility-wide diagnostic-storage quota (default 20 GB). Uploads that would exceed it are refused with 403.
- Schedule `GET /api/cron/media-upload-sessions` (hourly is enough; it uses `CRON_SECRET`) to abort expired multipart sessions so abandoned studies leave no orphaned parts.
- `EPRESCRIBING_ENDPOINT` (optional): e-prescribing relay URL. Without it, submitted medication orders enqueue outbox entries that stay `PENDING` and the queue reports `endpointConfigured: false` — the system never claims live transmission.
- Fonts in `assets/fonts` are bundled for PDF rendering (`outputFileTracingIncludes` in `next.config.ts`).

## How to use

**Hospital administrators:** set branding, prefix and triage protocol in *Hospital settings* → in *Medical documents* adopt catalogue templates (or create/import) → edit sections/fields/signatures → Submit → a second authorized person Approves (if independent approval is on) → Publish. To change a published template, click *New version*. Retire obsolete templates; historical documents stay intact.

**Doctors, nurses, lab scientists, radiologists:** register or find the encounter → *New document* → choose a published template → fill the draft (autosaves) → Submit → reviewer *Verify* (if required) → each required signatory records a signature (patients/witnesses: record their wet-ink signature with the attestation) → *Finalize*. Corrections: *Amend* (reason required). Upload images/videos/reports in *Diagnostic media* and set report status; release verified items to the patient.

**Patients:** open *Hospital documents* in the patient menu to view and download released reports and files.

## Pending / not implemented

- DICOM viewer, PACS, modality worklists (DICOM files are stored and downloadable; viewer integration requires a PACS/viewer service).
- HL7 v2 / FHIR APIs, LOINC/SNOMED CT/UCUM terminology services (fields for LOINC codes and UCUM units exist in lab templates; ICD-10 already exists platform-wide).
- Qualified/advanced electronic signatures (PKI); patient self-signing in the portal.
- Formularies, interaction checking, MAR-style administration recording and external pharmacy/e-prescribing integration; clinical scores; escalation rules for overdue observations; insurance eligibility/claims APIs.
- Database-level row security (isolation is enforced in the application layer); retention-driven deletion workflows; breach-investigation export tooling.
- Catalogue wording has not been clinically or legally reviewed — templates must be reviewed by each hospital before operational use. No legal-compliance claim is made.
